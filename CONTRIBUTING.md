# Contributing

Start with `npm ci` and `npm run demo`. Run `npm run check` before proposing a change.

Keep application-specific data, authentication, and business rules in adapters. Add a behavior test for bug fixes and changes to persistence, queries, rendering, or package boundaries. Use fictional fixtures. Never commit `.env`, API keys, local databases, employee information, or screenshots of internal systems.

Include a screenshot or short clip for visible UI changes. Test keyboard focus, narrow layouts, light/dark contrast, and reduced motion when relevant. Document adapter contract changes and record them in the changelog.

Open an issue or pull request in [this repository](https://github.com/fernando-freitas-alves/dashboard-kit). Explain the behavior you want to change and how you tested it.
